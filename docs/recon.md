# Binary reconnaissance: Metroid Dread 2.1.0

All numbers are for the 2.1.0 ExeFS (`main` build ID `646761F643AFEBB379EDD5E6A5151AF2CEF93DC1`)
and are regenerated by the tools below. Addresses use the conventional Switch image base
`0x7100000000`.

## How to reproduce

```sh
python tools/nso2elf.py orig/2.1.0/exefs/main orig/2.1.0/main.elf
python tools/recon/run.py --version 2.1.0            # no Ghidra needed
python tools/ghidra/analyze.py --version 2.1.0       # ~8 min import + auto-analysis + export
python tools/gen_functions_csv.py --version 2.1.0    # data/functions/*.csv, data/reflection_types.csv
```

`main` has a **1.82 GB `.bss`** (`0x7101d46060`–`0x7172a19000`). The game reserves almost
all of its memory statically rather than taking it from the SDK heap at startup.

`main`'s rodata is mostly linker metadata: `.rela.dyn` (3.5 MB, 145,813 `R_AARCH64_RELATIVE`
relocations) and `.eh_frame` (3.0 MB). Only about 0.7 MB is real constant data. Vtables and
pointer tables, which need relocation, are in `.data`. There are 2,760 static initialisers
in `.init_array`.

## Mercury reflection and mercury-engine-data-structures (MEDS)

- 3,025 of MEDS's 3,055 type names appear verbatim as strings in `main`.
- 21,901 of MEDS's 44,605 property names appear verbatim. The rest are presumably only
  present as CRC64 hashes.
- Each reflected type `T` has a getter: a `__cxa_guard`-protected static initialiser
  that builds the string `"T"`, calls the parent type's getter, and passes both to a
  per-type helper. That helper constructs a `base::reflection::CClass` (or `CEnumType`,
  `CCollectionType`, `CPointerType`, `CFlagsetType`) and stores `sizeof(T)` at
  descriptor offset `+0x18`.
- 2,485 getters were recovered: 2,346 classes, 85 pointer types, 10 enums, 2 collections, and 42
  whose descriptor kind wasn't identified.
- **Parents cross-check:** for classes, the parent recovered from the getter's call agrees with MEDS for
  2,265 types, MEDS has a parent that wasn't detected for 3, and 2 differ (`CSubAreaManager` and
  one nested type, both linked to `CSubAreaManager::CTunableSubAreaManager`).
- **`sizeof` for all 2,346 reflected classes** is in `data/reflection_types.csv`. Examples:
  `CActor` 0x1b8, `CEntity` 0x3d8, `CPlayerMovement` 0x2278, `CDoorLifeComponent` 0xc00. The largest
  is `base::snd::CSoundSystem` at 0x400940, followed by the E.M.M.I. AI components at
  about 0x2a700. One value fails the "subclass is at least as large as its parent" check
  (`CRodomithonXSuckAttack` 0x40 vs. its parent 0x190) and should be treated as unreliable.

## Surprises and notes

- **Game code is built without RTTI.** All 82 `type_info` objects in `main` belong to
  `nn::atk`, which Nintendo ships precompiled. Class names come from reflection, not RTTI.
- **No C++ exceptions.** No `__cxa_throw`, `__cxa_begin_catch` or personality-routine
  imports, so the game is most likely built with `-fno-exceptions`. `.eh_frame` is still emitted
  (unwind tables, probably for crash backtraces), which is what gives exact
  function bounds.
- **Identical-code folding:** the linker merged identical bodies, for example a lone `ret` shared by
  game code and `nn::atk` vtables. Some function addresses therefore stand for several source
  functions.
- **Build provenance:** a leftover path string names a Perforce workspace, project
  `PRJ_04`, the `Retail` configuration, and the output module `cazadora.nss`
  ("cazadora" is Spanish for "huntress", probably the internal codename). One assert path
  (`..\Base/global/RntVector.h`) leaks the engine's source layout.
- **Debug tooling ships in retail:** Dear ImGui configuration and log file names are present.
- Game-side Lua bindings are concentrated in one 449-entry table (scene, lighting,
  post-processing, camera) plus tables for the world graph, save data, GUI display objects
  and blackboard properties.
